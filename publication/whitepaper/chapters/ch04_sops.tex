\section{The FLOPS Limitation}
\label{sec:flops_limitation}

Floating-Point Operations Per Second (FLOPS) is the standard metric for measuring computational throughput. For a General Matrix Multiply (GEMM) of size $M \times N \times K$:

\[
\text{FLOPS} = \frac{2 \times M \times N \times K}{T_{\text{seconds}}}
\]

This metric treats every multiply-add as equivalent, regardless of operand precision. But consider:

\begin{center}
\begin{tabular}{lcc}
\toprule
\textbf{Scenario} & \textbf{FP32 GEMM} & \textbf{OIL4 GEMM} \\
\midrule
Weight precision & 32 bits & 4 bits \\
Bytes per weight & 4.0 & 0.5 \\
Weights per second (40\,GB/s) & 10B & 80B \\
MACs per second & 10B & 80B \\
FLOPS & 10\,GFLOPS & 80\,GFLOPS \\
FLOPS reports & SAME FORMULA & SAME FORMULA \\
\bottomrule
\end{tabular}
\end{center}

FLOPS cannot distinguish the 8$\times$ memory bandwidth advantage of OIL4 over FP32. SOPS fixes this.

\section{SOPS Definition}
\label{sec:sops_definition}

\begin{definition}[SOPS]
One SOPS equals $10^{21}$ (one sextillion) information-weighted operations per second, where each operation is normalized to FP32-equivalent information throughput.
\end{definition}

\begin{equation}
\text{SOPS} = \frac{E \times \IW}{T \times 10^{21}}
\label{eq:sops_definition}
\end{equation}

where:
\begin{itemize}
    \item $E$ = number of weight elements processed
    \item $\IW = 32 / \BPW$ = info weight (FP32-equivalent ops per weight)
    \item $T$ = elapsed time in seconds
    \item $\BPW$ = bits per weight element
\end{itemize}

\section{Info Weight}
\label{sec:info_weight}

\begin{definition}[Info Weight]
The Info Weight (IW) of a format measures how many FP32-equivalent weight operations one element of that format represents, in terms of memory subsystem throughput:
\[
\IW = \frac{32}{\BPW}
\]
\end{definition}

\subsection{Physical Meaning}

A BINARY weight ($\BPW = 1$) at $\IW = 32$ means: processing one BINARY weight consumes $1/32$nd the memory bandwidth of processing one FP32 weight. Therefore, you can process 32$\times$ more BINARY weights per byte of memory bandwidth.

This is NOT about compute parallelism (SIMD). It is about information density in the memory subsystem. The SIMD speedup is captured in the TIME denominator (faster processing = smaller $T$ = higher SOPS).

\section{Key Theorems}
\label{sec:sops_theorems}

\begin{mythm}[Info Weight = Memory Bandwidth Ratio]{thm:iw_bw_ratio}
For format $A$ ($\BPW_a$) and format $B$ ($\BPW_b$):
\[
\frac{\IW(A)}{\IW(B)} = \frac{\text{Memory\_BW\_ratio}(A/B)}{}
\]
That is, the ratio of Info Weights equals the ratio of memory bandwidth advantages.
\end{mythm}

\begin{proof}
\[
\frac{\IW(A)}{\IW(B)} = \frac{32/\BPW_a}{32/\BPW_b} = \frac{\BPW_b}{\BPW_a}
\]
Memory bandwidth ratio:
\[
\frac{BW/\BPW_a}{BW/\BPW_b} = \frac{\BPW_b}{\BPW_a}
\]
Therefore $\IW(A)/\IW(B) = \text{Memory\_BW\_ratio}(A/B)$. $\square$
\end{proof}

\begin{mythm}[SOPS/FLOPS Ratio]{thm:sops_flops_ratio}
For a format with $\BPW$, the ratio of SOPS to FLOPS (for a GEMM) is:
\[
\frac{\text{SOPS}}{\text{FLOPS}} = \frac{16}{\BPW \times 10^{21}}
\]
\end{mythm}

\begin{proof}
\[
\text{SOPS} = \frac{E \times 32/\BPW}{T \times 10^{21}}
\]
\[
\text{FLOPS} = \frac{2E}{T}
\]
\[
\frac{\text{SOPS}}{\text{FLOPS}} = \frac{32/\BPW}{2 \times 10^{21}} = \frac{16}{\BPW \times 10^{21}}
\]
For OIL4 ($\BPW = 4$): ratio $= 4 \times 10^{-21}$. For FP32 ($\BPW = 32$): ratio $= 0.5 \times 10^{-21}$. The ratio is format-dependent, proving FLOPS cannot capture the format advantage. $\square$
\end{proof}

\subsection{CPU Memory Hierarchy Impact}

For a 64M-parameter model:
\begin{itemize}
    \item FP32 (256\,MB) $\to$ exceeds L3, must use main RAM
    \item OIL4 (32\,MB) $\to$ fits in L3 cache!
    \item TERNARY (10.2\,MB) $\to$ fits in L2 cache!
    \item BINARY (8\,MB) $\to$ fits in L2 cache!
\end{itemize}

Smaller formats access faster memory tiers, compounding the bandwidth advantage beyond the raw BPW ratio.

\section{SIMD Independence}
\label{sec:simd_independence}

\begin{quote}
\textbf{Key insight:} SIMD width does NOT affect Info Weight. This is intentional.
\end{quote}

\begin{itemize}
    \item AVX2 processes 64 OIL4 weights per load (256 bits / 4 bits)
    \item AVX2 processes 8 FP32 weights per load (256 bits / 32 bits)
    \item Ratio: $64/8 = 8\times$
    \item Memory ratio: $4/0.5 = 8\times$
\end{itemize}

Both ratios are $8\times$. The SIMD advantage IS the memory advantage. They are the same physical phenomenon viewed differently. The SIMD speedup shows up in the TIME measurement, not in the info weight.

\subsection{Landauer's Limit}

Landauer's Principle: minimum energy per bit operation $= kT \ln 2 \approx 3 \times 10^{-21}$\,J at room temperature.

\[
1 \text{ SOPS} = 10^{21} \text{ ops/sec} \implies E_{\min} = 3 \text{ watts}
\]

Physical limit: 3 watts for 1 SOPS. Current reality: 100\,watts for 0.092 pSOPS. Efficiency gap: $\sim 10^{12}$.

\section{SopsCounter API}
\label{sec:sops_api}

The implementation lives in \texttt{include/oil/sops.h}:

\begin{lstlisting}[language=C++,caption={SopsCounter basic usage}]
#include "oil/sops.h"
using namespace oil;

SopsCounter counter;
counter.cpu_ghz = 3.0;

counter.start();
// ... perform quantized operations ...
counter.record(5, element_count); // 5 = OIL4 format index
counter.stop();

printf("SOPS: %.4f %s\n",
       counter.best_value(), counter.best_unit());
\end{lstlisting}

\begin{lstlisting}[language=C++,caption={Multi-threaded SOPS measurement}]
std::atomic<double> max_sops{0.0};

void worker(int thread_id, int64_t ops) {
    SopsCounter local;
    local.cpu_ghz = 3.0;
    local.start();
    // ... do quantized work ...
    local.record(5, ops);  // OIL4
    local.stop();
    double s = local.sops();
    double prev = max_sops.load();
    while (s > prev &&
           !max_sops.compare_exchange_weak(prev, s)) {}
}
\end{lstlisting}
